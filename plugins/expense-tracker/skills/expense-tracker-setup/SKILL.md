# Настройка учёта трат

Проведи пользователя по шагам ниже. **Каждый шаг проверяй командой и показывай результат одной строкой**,
прежде чем идти дальше. Если что-то не так, остановись на этом шаге, объясни и предложи исправление.

**Пути.**
- Скрипты лежат в соседнем скилле: `${CLAUDE_SKILL_DIR}/../expense-tracker/scripts/`. В командах ниже
  `…/имя.py` — сокращение этого пути: подставляй его полностью.
- Справочники: `${CLAUDE_SKILL_DIR}/../expense-tracker/references/`.
- Если переменная не подставилась, возьми базовый каталог этого скилла, показанный при загрузке,
  и подставь `<он>/../expense-tracker/…`.
- Переменные shell между вызовами не сохраняются, поэтому пиши полный путь в каждой команде.

Если пользователь просит одно действие («перелогинь банк», «подключи Ленту»), сделай только
соответствующий шаг (6 или 7) и проверку.

## 0. Что уже есть

`python3 "${CLAUDE_SKILL_DIR}/../expense-tracker/scripts/config.py" check`, затем `… config.py show`.

- **Код 0** — настройка уже есть. Покажи, что настроено (data source, наличие профиля и
  `chrome-profile`), и спроси, что переделать. Всё заново без спроса не делай.
- **Код 2** — идём по шагам.

Каталог данных по умолчанию — `~/.expense-tracker`. Другой каталог задаёт переменная `EXPENSE_TRACKER_HOME`.
В каталоге лежат:
- `config.json`;
- `profile.md`;
- `chrome-profile/` — отдельный профиль Chrome с cookies банка и магазинов;
- `ypay-feed-hash`.

В репозиторий плагина это не попадает.

## 1. Зависимости

| Что | Проверка | Если нет |
|---|---|---|
| Python 3.9+ | `python3 --version` | На macOS подойдёт системный `python3`; если его нет — `xcode-select --install` (с согласия). На Linux — пакет `python3` |
| uv | `uv --version` | `curl -LsSf https://astral.sh/uv/install.sh \| sh` (или `brew install uv`, если есть Homebrew) — только с согласия. См. ниже про PATH |
| Google Chrome | macOS: `mdfind "kMDItemCFBundleIdentifier == 'com.google.Chrome'"` печатает путь, где бы ни стоял; пусто — проверь `ls -d "/Applications/Google Chrome.app" ~/Applications/"Google Chrome.app"`<br>Linux: `command -v google-chrome \|\| command -v google-chrome-stable \|\| command -v chromium \|\| command -v chromium-browser` | Пусть пользователь поставит Chrome. Свой путь можно задать через `EXPENSE_TRACKER_CHROME` |

`python3` нужен только для `config.py`, `guess_combo.py` и `build_report.py` (стандартная библиотека).
Скрипты с браузером запускаются через `uv run`: uv сам берёт Python 3.10+ и ставит `playwright`.
Браузеры Playwright не скачиваются, используется установленный Chrome.

**uv после установки.** Установщик кладёт uv в `~/.local/bin` и правит профиль shell, но окружение
текущей сессии Claude Code не обновляется. Проверь `~/.local/bin/uv --version`. Если `uv` не находится
в PATH, в шагах 6–7 пиши полный путь `~/.local/bin/uv run …` или попроси пользователя перезапустить
Claude Code.

На Linux нужна графическая сессия (`DISPLAY` или `WAYLAND_DISPLAY`). Дополнительные флаги Chrome задаются
через `EXPENSE_TRACKER_CHROME_ARGS`, например `--password-store=basic`, если мешает связка ключей.

## 2. Notion-коннектор

1. Проверь, что доступны инструменты Notion (`notion-fetch`, `notion-search`, `notion-create-database`).
   Вызови `notion-get-self`. Он должен ответить без ошибки.
2. Инструментов нет — попроси подключить Notion в claude.ai: «Settings → Connectors → Notion».
   Нужен свой аккаунт Notion (бесплатного хватает). Коннектор claude.ai появляется в Claude Code, только
   если вход в Claude Code выполнен аккаунтом claude.ai (не API-ключом и не через Bedrock/Vertex).
   `/mcp` только показывает подключённое и переавторизует его, добавить коннектор им нельзя.
   После подключения перезапустить сессию и повторить шаг.
3. На тарифах без безлимитного SQL (всё, кроме Business и Enterprise с Notion AI) у SQL-запросов
   коннектора общая почасовая квота. Поэтому на шаге 4 нужно запасное представление.

## 3. Короткий расспрос

Задай вопросы одним сообщением, отвечать можно коротко:
1. Какими картами или счетами платишь? Варианты для «Счёт», например «Яндекс Пэй», «Другая карта», «Наличные».
2. Где покупаешь чаще всего? Магазины у дома, сети, кафе, сервисы доставки. Если знаешь, как они
   подписаны в банке, тоже напиши.
3. Кому чаще всего переводишь и что обычно значат эти переводы? Долг, общие покупки, «скинул за обед».
   Хватит имени, как оно видно в банке.
4. Как отмечать подарки и общие покупки? По умолчанию подарок — «<Товар> (в подарок)», чужая часть
   общей покупки — «<Товар> (за <кого>)».
5. Нужна ли Лента: чеки по карте лояльности и онлайн-заказы? Нужна ли Яндекс Еда?

Ответы пригодятся в шагах 4 и 5.

## 4. База в Notion

Спроси: создать новую базу или подключить существующую?

**Новая** — по `references/notion-schema.md`, раздел «Создание через Notion-коннектор»:

1. Создай страницу «Расходы».
   - Если пользователь назвал, где её держать, создай её под этой страницей.
   - Иначе используй `creation_mode: "draft"` и потом скажи, что страница личная и её можно перенести.
2. Создай базу `notion-create-database`:
   - `parent` — эта страница;
   - `title: "Расходы по товарам"`;
   - `schema` из справочника;
   - варианты «Счёт» и «Где» замени ответами на вопросы 1–2. Стартовые сети можно оставить.
3. Создай рекомендуемые представления (`notion-create-view`, таблица в справочнике). Если какое-то
   не создалось, это не блокирует настройку: скажи об этом и иди дальше.
4. Получи значения для `config.json` (общий подшаг ниже).

**Существующая:**
1. Попроси ссылку и сделай `notion-fetch`.
2. Сверь свойства со схемой. Недостающие предложи добавить, отличающиеся по имени — переименовать.
   Только с согласия.
3. Варианты select не теряй: при `ALTER` перечисляй все.
4. Получи значения для `config.json` (общий подшаг ниже).

**Значения для `config.json`** (для обеих веток):
- `notion.data_source` — `collection://…` из тега `<data-source>` в ответе `notion-create-database`
  или `notion-fetch` базы. Если data source несколько, спроси, в каком из них траты.
- `notion.default_view` — ссылка на представление по справочнику, раздел «Представление по умолчанию»
  (id представления — из того же `notion-fetch`). Подойдёт Default view или любая таблица без фильтров.
  Задай ей сортировку по Дате по убыванию; у существующей базы — только с согласия.

**Проверка:**
- `notion-query-data-sources` в SQL: `SELECT COUNT(*) FROM [collection://…]`.
- То же в view-режиме по ссылке на представление с `page_size: 1`.

Оба должны ответить без ошибки.

## 5. config.json и profile.md

```bash
python3 "${CLAUDE_SKILL_DIR}/../expense-tracker/scripts/config.py" set notion.data_source "collection://…"
python3 "${CLAUDE_SKILL_DIR}/../expense-tracker/scripts/config.py" set notion.default_view "https://www.notion.so/…?v=…"
python3 "${CLAUDE_SKILL_DIR}/../expense-tracker/scripts/config.py" set timezone "<IANA-пояс>"
python3 "${CLAUDE_SKILL_DIR}/../expense-tracker/scripts/config.py" check
```

**Часовой пояс.** `config.py show` показывает действующий пояс и откуда он взят. Если системный подходит,
команду `set timezone` можно пропустить. Иначе задай IANA-имя пояса пользователя (вида `Europe/…`,
`Asia/…`). Скрипт переводит время операций банка в этот пояс.

**Проверка:** `config.py check` вернул код 0. Предупреждения, если есть, озвучь.

**Профиль.** Скопируй шаблон, если профиля ещё нет:

```bash
P="$(python3 "${CLAUDE_SKILL_DIR}/../expense-tracker/scripts/config.py" path profile)"; [ -e "$P" ] || cp "${CLAUDE_SKILL_DIR}/../expense-tracker/references/profile-template.md" "$P"; ls -l "$P"
```

Затем заполни его ответами из шага 3:
- счета;
- магазины и как они видны в банке;
- люди и переводы;
- правила подарков и общих покупок.

Строки с пометкой *(пример)* удали. Пустые разделы оставь с заголовками — их будет дописывать
`expense-tracker`. Номера карт, телефоны и адреса не записывай.

**Проверка:** профиль читается, в нём нет строк «(пример)». Покажи пользователю короткую выжимку того,
что записано.

## 6. Вход в банк (Яндекс Пэй)

1. Предупреди: «Сейчас откроется окно Chrome с отдельным профилем учёта трат. Войди в Яндекс ID и введи
   PIN или код банка. Мне пароли не нужны и я их не вижу». Дождись согласия.
2. Запусти `uv run "${CLAUDE_SKILL_DIR}/../expense-tracker/scripts/ypay.py" login`. Окно разворачивается,
   команда сразу завершается. Первый запуск может занять минуту: uv ставит `playwright`.
3. Пользователь сказал, что вошёл, — проверь: `uv run "…/ypay.py" -n 3`.
   - Должны напечататься 3 последние операции. Показывай их коротко.
   - Код 3 — вход не завершён. Попроси закончить вход в окне и повтори проверку.

Сессия банка живёт около 15 минут. Потом при сверке понадобится снова ввести PIN: скилл `expense-tracker`
спросит об этом сам. Яндекс ID остаётся залогиненным в профиле.

## 7. Лента и Яндекс Еда (по желанию)

**Лента.**
1. Предупреди об окне и получи согласие.
2. `uv run "…/lenta.py" login` — войти на lenta.com.
3. Проверь: `uv run "…/lenta.py" shop`. Должен напечататься список чеков за 31 день, пусто тоже
   допустимо. Код 3 — входа нет.

**Яндекс Еда** — тот же Яндекс ID, что у банка, отдельный вход обычно не нужен.
1. Проверь: `uv run "…/eda.py" orders`.
2. Если код 3, но банк на шаге 6 работал, скорее всего заказов просто нет. Если сомнения, с согласия
   запусти `eda.py login`.

Скрипты держат окно Chrome свёрнутым и не открывают новых вкладок. Headless-режим и подмена
User-Agent не используются.
