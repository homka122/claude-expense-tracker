# Отчёт о тратах за период

Результат — самодостаточный HTML-файл с графиками и блоком выводов, построенный по строкам базы Notion.

**Пути.**
- Скрипты лежат в соседнем скилле: `${CLAUDE_SKILL_DIR}/../expense-tracker/scripts/`. В командах ниже
  `…/` — сокращение этого пути: подставляй его полностью.
- Если переменная не подставилась, возьми базовый каталог этого скилла, показанный при загрузке,
  и подставь `<он>/../expense-tracker/scripts/`.
- Образец выводов: `${CLAUDE_SKILL_DIR}/../expense-tracker/references/findings-template.html`.

**Главное правило: все числа в выводах берутся из вывода скрипта или считаются кодом по CSV.**
В уме не считай.

## 1. Период и настройка

1. **Период.**
   - Месяц назван — бери его.
   - Сказано просто «итоги месяца» — бери последний полный месяц.
   - «За этот месяц» — с 1-го числа по сегодня.

   Границы: `[первый день, первый день следующего месяца)`.
2. **Настройка.** `python3 "…/config.py" check`. Код 2 — предложи `expense-tracker-setup` и остановись.
   Дальше `python3 "…/config.py" show`: из него нужны `settings.notion.data_source`,
   `settings.notion.default_view` и `home`.
3. **Сверка.** Отчёт честный, только если месяц сверен с банком. Если пользователь не просил иначе,
   спроси одной строкой: «Сначала сверить <месяц> с банком?»
   - Да — пройди сверку по скиллу `expense-tracker` и вернись сюда.
   - Нет — продолжай, а в блоке «Учёт» укажи, что сверки не было.

## 2. Выгрузка из Notion в CSV

1. Сделай `notion-fetch` по `data_source` и возьми точные имена колонок из `<sqlite-table>`.
2. Посчитай контрольные числа:

   ```sql
   SELECT COUNT(*) AS n, SUM("Сумма") AS total FROM [collection://…]
   WHERE "date:Дата:start" >= ? AND "date:Дата:start" < ?
   ```

   `params: ["2026-10-01", "2026-11-01"]`.
3. Выгрузи строки:

   ```sql
   SELECT "date:Дата:start" AS date, "Товар" AS item, "Категория" AS category, "Необходимость" AS necessity,
          "Где" AS "where", "Сумма" AS amount, "Детали" AS details, "Количество" AS qty, "Тип" AS type
   FROM [collection://…]
   WHERE "date:Дата:start" >= ? AND "date:Дата:start" < ?
   ORDER BY "date:Дата:start"
   ```

   Строк больше, чем вернулось за раз, — дочитай через `LIMIT … OFFSET …`.
4. Если SQL ответил ошибкой квоты, читай всё через `{"data": {"mode": "view", "view_url": "<default_view>",
   "page_size": 100}}`.
   - Листай по `next_cursor`.
   - Строки периода отфильтруй кодом по «Дата».
   - Контрольные `n` и `total` в этом случае посчитай кодом по прочитанному.
5. Запиши CSV в `<home>/reports/<YYYY-MM>.csv` (`mkdir -p` каталога). Формат:
   - кодировка UTF-8, разделитель `;`, первая строка — заголовок;
   - поле с `;` или кавычками заключи в двойные кавычки по правилам CSV;
   - удобнее всего записать строки скриптом на `python3` через модуль `csv`.

```text
date;item;category;necessity;where;amount;details;qty;type
2026-10-03;Молоко 2,5% 1 л;Молочное и яйца;Базовое;Пятёрочка;99;;1;Еда
2026-10-03;Шоколад (в подарок);Снеки и сладкое;Необязательное;Пятёрочка;149;;1;Еда
2026-10-05;Хлеб;Хлеб;Базовое;Пятёрочка;59;состав подобран по прошлым ценам;1;Еда
```

Колонки:

| Колонка | Свойство | Обязательна |
|---|---|---|
| `date` | Дата, `YYYY-MM-DD` | да |
| `item` | Товар | да |
| `amount` | Сумма, число (точка или запятая) | да |
| `category` | Категория | |
| `necessity` | Необходимость | |
| `where` | Где | |
| `details` | Детали | |
| `qty` | Количество | |
| `type` | Тип | нужна при группировке по типу |

Вместо английских имён можно оставить русские названия свойств. Полное описание формата —
`python3 "…/report/build_report.py" --help`.

**Подарки и подобранный состав** скрипт распознаёт сам:
- подарок — `(в подарок)` или `(за <кого>)` в названии, название начинается с «Подарок»
  или «Детали» начинаются с «в подарок»;
- подобранный состав — слово «подобран» в «Детали».

Если в `profile.md` подарки помечаются иначе, добавь колонку `gift` со значениями `да`/`нет`. Так же
можно явно задать колонку `guessed`.

**Проверка выгрузки.** Посчитай кодом по CSV число строк и сумму `amount`. Они должны совпасть с
контрольными `n` и `total` до копейки. Не совпало — найди потерянные строки, отчёт пока не строй.

## 3. Личные группы (необязательно)

Правила отчёта можно хранить в `<home>/report-config.json`. Образец —
`…/report/config.example.json`. Ключи:
- `big_amount` — порог «крупной» покупки, по умолчанию 2000 ₽;
- `big_categories` — категории, которые всегда считаются крупными, по умолчанию «Электроника»;
- `group_by` — `"category"` или `"type"`;
- `groups` — переименовать или слить категории;
- `base_label`;
- `habits` — привычки, которые считаются отдельно, например
  `{"label": "Кофе с собой", "match": ["Капучино", "Латте"], "unit": "шт"}`.
  - `match` — подстроки названия;
  - `categories` и `where` — фильтры;
  - `unit: "раз"` считает визиты.

Файла нет, а в профиле или в прошлых записях видны явные привычки (кофе навынос, фастфуд, такси) —
предложи завести их в конфиг. Без согласия файл не создавай. Привычки пользователя в код и
в репозиторий не вносятся.

## 4. Построить отчёт

```bash
python3 "…/report/build_report.py" --csv "<home>/reports/2026-10.csv" --title "Октябрь 2026" \
    --out "<home>/reports/2026-10.html" [--config "<home>/report-config.json"]
```

Скрипт печатает:
- путь к HTML;
- JSON с итогами: `total`, `everyday`, `perDay`, `big`, `bigItems`, `optional`, `optionalShare`,
  `gifts`, `giftRows`, `guessedRows`, `habitsTotal`, `days`, `rows`;
- списки `groups`, `optionalGroups`, `habits`, `where`.

Это фактура для выводов. Предупреждения о пропущенных строках (без даты или суммы) разбери и исправь
в CSV.

## 5. Выводы

1. Напиши `<home>/reports/2026-10-findings.html` по образцу `references/findings-template.html`:
   - те же классы;
   - карточка «Выводы» — 3–5 пунктов;
   - карточка «Что улучшить» — таблица «действие → ≈ экономия в месяц» и пункт «Учёт»;
   - подпись источника.

   Числа в образце выдуманы, их не переносить.

   Что должно быть в выводах:
   - **Главное.** Всего, сколько из этого крупные покупки, сколько в день без них.
   - **Структура.** Продукты против готовой еды и кафе, доля необязательного.
   - **Привычки.** Что повторяется, сколько раз, средняя цена.
   - **Переплаты.** Сборы за доставку, тот же товар дороже в другом месте, мелкие заказы.
   - **Подарки и траты на других** — отдельной суммой, они уже внутри итога.
   - **Экономия.** Оценки реалистичные, при тех же привычках, только чуть иначе. Каждую посчитай
     кодом из строк CSV: например, сумма сборов за доставку × доля заказов, которые можно объединить.
   - **Учёт.** Сверен ли месяц, сколько строк подобрано по ценам (`guessedRows`), что не записано.
2. Пересобери отчёт с `--findings "<home>/reports/2026-10-findings.html"` и тем же `--out`.

## 6. Показать

1. Открой файл:
   - macOS: `open "<путь>"`;
   - Linux: `xdg-open "<путь>"`.
2. В чат дай 3–5 строк: итог, в день без крупных, главная группа, главная возможность сэкономить и путь
   к файлу.
3. Если в базе за период есть неопределённости, назови их одной строкой: не сверено, подобрано
   по ценам, пустые категории.

Отчёт, CSV и выводы лежат в каталоге данных пользователя. В репозиторий плагина их не клади.
Пользователь может попросить сохранить отчёт в другое место.
