# Учёт трат

Пользователь просто обсуждает траты. Ты смотришь платежи, угадываешь, что это было, коротко
спрашиваешь, он отвечает — ты записываешь в Notion. Запросы, оформление строк и сверка сумм — твоя
работа, без лишних вопросов пользователю.

**Пути.**
- Скрипты: `${CLAUDE_SKILL_DIR}/scripts/`. Справочники: `${CLAUDE_SKILL_DIR}/references/`.
- Если переменная не подставилась, возьми базовый каталог этого скилла, который показан при загрузке.
- Переменные shell между вызовами не сохраняются, поэтому пиши полный путь в каждой команде.
- Python-скрипты с браузером запускай через `uv run`, остальные — через `python3`.

**Справочники** — читай, когда нужна деталь:
- `references/conventions.md` — правила учёта: что строка, что пропускать, подарки, переводы, весовые.
- `references/notion-schema.md` — свойства базы, варианты select, примеры SQL и записи.

## 1. Настройка и профиль

1. Проверь настройку: `python3 "${CLAUDE_SKILL_DIR}/scripts/config.py" check`.
   - Код 2 — настройки нет или она битая. Предложи пройти настройку (скилл `expense-tracker-setup`)
     и дальше не иди.
2. Прочитай настройки: `python3 "${CLAUDE_SKILL_DIR}/scripts/config.py" show`. Там JSON, из него нужны
   `settings.notion.data_source` (`collection://…`), `settings.notion.default_view` и путь `profile.path`.
3. Прочитай `profile.md` по этому пути. Из профиля берутся:
   - как магазины видны в банке;
   - привычные покупки и цены;
   - что значат переводы конкретным людям;
   - правила пользователя (подарки, возмещения, что не записывать).

   Профиля нет — работай без него. В конце предложи завести профиль по шаблону `references/profile-template.md`.

## 2. Что уже записано

1. Сделай `notion-fetch` по `notion.data_source`: так видна актуальная схема и `<sqlite-table>`
   с точными именами колонок. Варианты select могли поменяться.
2. Прочитай последние записи через `notion-query-data-sources` (SQL, пример — в `notion-schema.md`):
   `ORDER BY "date:Дата:start" DESC LIMIT 50`.
3. Если SQL ответил ошибкой квоты, читай через запасное представление:
   `{"data": {"mode": "view", "view_url": "<notion.default_view>", "page_size": 100}}`.
   - Если `has_more`, передай `next_cursor` как `start_cursor`.
   - Если `default_view` не задан, скажи об этом и предложи `expense-tracker-setup`.
4. Последняя дата в базе — точка, с которой сверяем. Если пользователь назвал период, бери его.
5. Запомни, как оформлены свежие строки: названия, «Где», «Счёт», категории, детали. Новые строки
   оформляй так же.

## 3. Платежи из банка

```bash
uv run "${CLAUDE_SKILL_DIR}/scripts/ypay.py" --since <YYYY-MM-DD> --json
```

Скрипт печатает JSON Lines. Поля:
- `date`;
- `amount` — минус означает списание;
- `currency`;
- `status` — `CLEAR`, `HOLD` или `FAIL`;
- `title` и `description` — как операция подписана в банке;
- `cashback`.

Без `--since` скрипт отдаёт последние `-n` операций (по умолчанию 20).

- **Код выхода 3** — нет сессии банка. Сессия живёт около 15 минут, потом банк просит PIN или код.
  1. Скажи пользователю, что нужен вход, и предупреди: откроется окно Chrome с отдельным профилем.
  2. Только после согласия запусти `uv run "${CLAUDE_SKILL_DIR}/scripts/ypay.py" login`. Команда разворачивает
     окно и сразу завершается.
  3. Дождись, пока пользователь скажет, что вошёл, и повтори запрос.
- Пропусти `FAIL`, поступления (положительная сумма) и кешбэк баллами. `HOLD` — см. `conventions.md`.
- Отметь платёж как записанный, если в базе за ту же дату (±1 день) есть строки с той же суммой.
  Суммы по дням и платежам считай кодом (`python3` по JSON Lines), не в уме.

## 4. Состав покупок

**Лента** — чеки из магазина по карте лояльности и онлайн-заказы:

```bash
uv run "${CLAUDE_SKILL_DIR}/scripts/lenta.py" shop --since <D> [--until <D>]   # список чеков: id, время, сумма, магазин
uv run "${CLAUDE_SKILL_DIR}/scripts/lenta.py" shop-detail <id>                 # позиции: qty, весовой ли, цена, сумма
uv run "${CLAUDE_SKILL_DIR}/scripts/lenta.py" orders                           # онлайн-заказы: номер, статус, сумма
uv run "${CLAUDE_SKILL_DIR}/scripts/lenta.py" order <num>                      # состав онлайн-заказа текстом
```

Код 3 — нет входа в Ленту. Спроси пользователя и, если он согласен, запусти `lenta.py login`
(разворачивает окно).

**Яндекс Еда** и магазины в ней. В банке такие платежи подписаны «Яндекс.Еда».

```bash
uv run "${CLAUDE_SKILL_DIR}/scripts/eda.py" orders        # список заказов
uv run "${CLAUDE_SKILL_DIR}/scripts/eda.py" order <nr>    # позиции, сборы, итог
```

Код 3 — нет входа в Яндекс ID или заказов нет вовсе. Еда использует тот же Яндекс ID, что банк.
- Если `ypay.py` работает, а Еда отвечает 3, вероятно, заказов просто нет.
- Иначе с согласия пользователя запусти `eda.py login` (разворачивает окно).

**Без чека** подбери состав по прошлым ценам того же магазина. Цены бери из прошлых строк базы
(SQL по «Где») и из профиля:

```bash
python3 "${CLAUDE_SKILL_DIR}/scripts/guess_combo.py" 412 "Хлеб=59" "Сыр=254" "Молоко=99" "Кефир=89" [--tolerance 5] [--max-items 4]
```

Цены можно передать файлом: `--prices prices.json` с содержимым `[{"name": …, "price": …}]`.
Подобранное покажи как догадку. При записи пометь в «Детали»: «состав подобран по прошлым ценам».

## 5. Показать и спросить

Покажи незаписанное по дням, от свежих к старым, одним коротким пронумерованным списком с догадками.
Пример (данные выдуманы):

```
Не записано с 12 октября:

14 окт
 1. 412 ₽  Пятёрочка — чека нет; по прошлым ценам похоже на хлеб + сыр + молоко
 2. 62 ₽   Транспорт — метро
13 окт
 3. 2 318 ₽  Лента — чек есть, 11 позиций, запишу по чеку
 4. 500 ₽  перевод «Иван И.» — за что?
 5. 1 290 ₽  холд, «ONLINE STORE» — что это?
```

- Пользователь отвечает номерами: «4 — обед пополам», «5 не записывай», «да».
- **В Notion пиши только после ответа.** «Доверяю», «просто добавь», «да» на весь список означает:
  записать всю показанную пачку так, как предложено. «Пропусти», «пофиг» — не записывать.
- Отвечай коротко. Не выводи сырые выгрузки целиком. Токены, cookies и заголовки браузера
  не печатай никогда.

## 6. Записать

1. Запиши строки через `notion-create-pages`:
   - `parent: {"type": "data_source_id", "data_source_id": "<uuid из notion.data_source без collection://>"}`;
   - одна страница = одна позиция чека;
   - пачка до 100 страниц за вызов;
   - `allow_async: false`: иначе запись уходит в фон, и сверка на шаге 7 может прочитать базу раньше,
     чем строки появятся. Если ответ всё же пришёл как `async_task`, дождись `succeeded` через
     `notion-get-async-task`.

   Пример свойств одной строки:

```json
{"Товар": "Молоко 2,5% 1 л", "date:Дата:start": "2026-10-14", "date:Дата:is_datetime": 0,
 "Сумма": 99, "Количество": 1, "Единица": "шт", "Цена за ед.": 99,
 "Категория": "Молочное и яйца", "Тип": "Еда", "Необходимость": "Базовое",
 "Где": "Пятёрочка", "Источник": "Чек", "Счёт": "Яндекс Пэй", "Детали": ""}
```

2. Нужного варианта select нет (новый магазин, категория, карта) — добавь его через
   `notion-update-data-source`.
   - В `ALTER COLUMN … SET SELECT(...)` перечисли **все** старые варианты плюс новый.
   - Скажи об этом одной строкой.
3. Правила оформления смотри в `conventions.md`: весовые по факту, сборы доставки отдельной строкой,
   подарки «(в подарок)», общие покупки «(за <кого>)», возмещения нетто.

## 7. Сверить и запомнить

1. После записи сверь суммы. Прочитай записанное за период через SQL:
   `SUM("Сумма")` по `"date:Дата:start"`; при квоте — через view.
   - Сравни с банком по дням кодом.
   - Итог скажи одной строкой: «Записано 14 строк, суммы по дням сходятся с банком».
   - Если не сходится, назови день и разницу.
2. Если выяснился **устойчивый** факт, допиши его в соответствующий раздел `profile.md`. Например:
   - как магазин подписан в банке;
   - обычная цена товара;
   - что значит перевод этому человеку;
   - новое правило пользователя.

   Скажи одной строкой: «В профиль: «SHOP 24» в банке = Магазин у дома». Разовые события,
   номера карт, телефоны и адреса в профиль не пиши.

## Вопросы «сколько я потратил на …» и «что я покупал»

Отвечай по базе через SQL с фильтром по периоду и «Категория» / «Где» / «Товар».
- Числа считай запросом (`SUM`, `COUNT`), не в уме.
- Если за период есть незаписанные платежи, скажи об этом. Предложи сначала сверить.
- Полный отчёт за месяц с графиками делает скилл `expense-report`.
