# Схема базы Notion «Расходы по товарам»

База лежит на странице «Расходы». Одна строка базы соответствует одной позиции чека, а не всему платежу.
Названия страницы и базы можно поменять: скиллы находят базу по `notion.data_source` из `config.json`,
а не по имени. На имена **свойств** опираются запись, сверка и отчёт, поэтому их лучше не переименовывать.
Если переименовали, поправьте и запросы.

## Свойства

| Свойство | Тип | Что хранит |
|---|---|---|
| **Товар** | title | Название позиции, как в чеке, только понятнее: «Молоко 2,5% 1 л», «Метро», «Подписка на музыку». Подарок: «… (в подарок)» |
| **Дата** | date | Дата покупки без времени (`is_datetime = 0`). В SQL раскрывается в колонки `date:Дата:start`, `date:Дата:end`, `date:Дата:is_datetime` |
| **Сумма** | number | Сколько заплачено за позицию, ₽. Учитывает скидки, а у весового товара соответствует фактическому весу |
| **Количество** | number | Штуки или килограммы, например 2 или 0.734 |
| **Цена за ед.** | number | Цена за штуку или килограмм |
| **Единица** | select | Варианты ниже |
| **Категория** | select | Что это за трата. Варианты ниже |
| **Тип** | select | Крупная группа. Варианты ниже |
| **Необходимость** | select | Базовое или Необязательное |
| **Где** | select | Магазин или заведение. Сервис доставки сюда не пишется, он идёт в «Детали» |
| **Источник** | select | Откуда известен состав |
| **Счёт** | select | Карта или счёт, с которых платили |
| **Чек** | text | Номер или ссылка на чек, если они есть |
| **Детали** | text | Свободный контекст: кому и через что, «холд», «состав подобран по прошлым ценам», «через Яндекс Еду», «за вычетом возмещения» |
| **Месяц** | formula | `formatDate(prop("Дата"), "YYYY-MM")` — для группировок в Notion. Скрипты его не используют |

Формула «Месяц» необязательна: ни скиллы, ни скрипты на неё не опираются, её можно заменить или удалить.

### Варианты select (цвет в скобках)

**Единица:** шт (default), кг (brown), упак. (blue), услуга (gray).

**Категория:**

| Продукты | Остальная еда | Быт и дом | Сервисы и прочее |
|---|---|---|---|
| Мясо и птица (red) | Снеки и сладкое (pink) | Бытовые товары (gray) | Транспорт (blue) |
| Рыба (blue) | Напитки (purple) | Кухонные товары (blue) | Связь / интернет (gray) |
| Молочное и яйца (yellow) | Готовая еда (orange) | Одежда (brown) | Подписки (green) |
| Бакалея (brown) | Доставка (gray) | Электроника (default) | VPN / хостинг (blue) |
| Хлеб (orange) | | Аптека / здоровье (red) | Игры / Steam (purple) |
| Овощи (green) | | | Стрижка / уход (pink) |
| Фрукты (orange) | | | Развлечения (yellow) |
| | | | Перевод на карту (purple) |
| | | | Другое (default) |

Отчёт объединяет семь продуктовых категорий (от «Мясо и птица» до «Фрукты») в группу «Продукты».
«Доставка» означает сборы за сборку и доставку, а не сами товары из заказа.
Набор категорий стартовый: лишние можно удалить, свои — добавить (см. «Подключение существующей базы»).

**Тип:** Еда (green), Бытовое (blue), Сервис (gray), Перевод (purple), Цифровое (purple).

Тип выводится из категории:
- Еда: продукты, снеки, напитки, готовая еда.
- Бытовое: бытовые и кухонные товары, одежда, электроника, аптека.
- Сервис: транспорт, связь, стрижка, доставка, развлечения.
- Цифровое: подписки, VPN / хостинг, игры.
- Перевод: перевод на карту.

**Необходимость:** Базовое (green), Необязательное (yellow).

**Где** — стартовый набор, дальше дополняется вашими магазинами: Лента (blue), Пятёрочка (red),
Перекрёсток (green), Магнит (red), ВкусВилл (green), Ozon (blue), Wildberries (purple).

**Источник:**
- Чек (green) — состав из чека или заказа.
- Ручной ввод (gray) — со слов пользователя.
- Скриншот (blue).
- Банк (purple) — есть только операция в банке, состав подобран или неизвестен.

**Счёт** — подставьте свои карты при настройке. По умолчанию: Яндекс Пэй (red), Другая карта (default),
Наличные (green).

## Создание через Notion-коннектор

1. Страница «Расходы»: `notion-create-pages` с `properties: {"title": "Расходы"}` и `allow_async: false`
   (id страницы нужен сразу, для следующего шага).
   - Если пользователь назвал, под какой страницей её держать, укажите её в `parent`.
   - Иначе создайте с `creation_mode: "draft"`: получится личная страница в корне workspace.
2. База: `notion-create-database`.
   - `parent: {"type": "page_id", "page_id": "<id страницы «Расходы»>"}`.
   - `title: "Расходы по товарам"`.
   - `schema` — оператор ниже. Перед вызовом замените варианты «Счёт» и «Где» на ответы пользователя.

```sql
CREATE TABLE (
  "Товар" TITLE,
  "Дата" DATE,
  "Сумма" NUMBER,
  "Количество" NUMBER,
  "Цена за ед." NUMBER,
  "Единица" SELECT('шт':default, 'кг':brown, 'упак.':blue, 'услуга':gray),
  "Категория" SELECT('Мясо и птица':red, 'Рыба':blue, 'Молочное и яйца':yellow, 'Бакалея':brown, 'Хлеб':orange, 'Овощи':green, 'Фрукты':orange, 'Снеки и сладкое':pink, 'Напитки':purple, 'Готовая еда':orange, 'Бытовые товары':gray, 'Кухонные товары':blue, 'Доставка':gray, 'Перевод на карту':purple, 'Игры / Steam':purple, 'Транспорт':blue, 'Стрижка / уход':pink, 'Электроника':default, 'VPN / хостинг':blue, 'Подписки':green, 'Одежда':brown, 'Связь / интернет':gray, 'Аптека / здоровье':red, 'Развлечения':yellow, 'Другое':default),
  "Тип" SELECT('Еда':green, 'Бытовое':blue, 'Сервис':gray, 'Перевод':purple, 'Цифровое':purple),
  "Необходимость" SELECT('Базовое':green, 'Необязательное':yellow),
  "Где" SELECT('Лента':blue, 'Пятёрочка':red, 'Перекрёсток':green, 'Магнит':red, 'ВкусВилл':green, 'Ozon':blue, 'Wildberries':purple),
  "Источник" SELECT('Чек':green, 'Ручной ввод':gray, 'Скриншот':blue, 'Банк':purple),
  "Счёт" SELECT('Яндекс Пэй':red, 'Другая карта':default, 'Наличные':green),
  "Чек" RICH_TEXT,
  "Детали" RICH_TEXT,
  "Месяц" FORMULA('formatDate(prop("Дата"), "YYYY-MM")')
)
```

Если коннектор не принял формулу, создайте базу без строки «Месяц». Потом добавьте её отдельно:
`notion-update-data-source` с `ADD COLUMN "Месяц" FORMULA('formatDate(prop("Дата"), "YYYY-MM")')`.
Не вышло и так — оставьте базу без неё.

3. В ответе `notion-create-database` есть тег `<data-source url="collection://…">`. Этот URL запишите
   в `notion.data_source`.
4. Представления создаются через `notion-create-view` с `database_id` новой базы и
   `data_source_id` = `collection://…`. Синтаксис `configure` описан в `notion://docs/view-dsl-spec`.

### Рекомендуемые представления

| Название | Тип | `configure` |
|---|---|---|
| Все товары | table | `SORT BY "Дата" DESC; SHOW "Товар", "Дата", "Сумма", "Категория", "Необходимость", "Количество", "Единица", "Цена за ед.", "Где", "Источник", "Чек"` |
| По категориям | board | `GROUP BY "Категория" HIDE EMPTY; SHOW "Товар", "Сумма", "Дата", "Необходимость"` |
| Базовое vs необязательное | board | `GROUP BY "Необходимость"; SHOW "Товар", "Сумма", "Категория", "Дата"` |
| Сумма по категориям | chart | `GROUP BY "Категория"; CHART bar AGGREGATE sum ON "Сумма" SORT y_descending HEIGHT large` |
| С фильтрами | table | `QUICK FILTER "Категория", "Необходимость", "Где"; SORT BY "Дата" DESC; SHOW "Товар", "Дата", "Сумма", "Категория", "Необходимость", "Где"` |
| Траты по дням | chart | `GROUP BY "Дата"; CHART column AGGREGATE sum ON "Сумма" SORT x_ascending STACK BY "Необходимость"` |

Notion может сгруппировать «Траты по дням» не по дням, а по неделям или месяцам. Тогда переключите
группировку на «День» в настройках графика.

### Представление по умолчанию (`notion.default_view`)

Это таблица, которую Notion создаёт вместе с базой: Default view, все свойства. Для неё полезно задать
сортировку по Дате по убыванию (`notion-update-view`, `SORT BY "Дата" DESC`).

Через это представление скилл читает базу в режиме `mode: "view"`. Так делают, когда кончилась
почасовая квота SQL. Квота общая на workspace и есть на тарифах без безлимитного SQL.

Как получить ссылку:
1. Сделайте `notion-fetch` базы и возьмите id представления Default view.
2. Соберите `https://www.notion.so/<id базы без дефисов>?v=<id представления без дефисов>`.
3. Проверьте: `notion-query-data-sources` с `{"data": {"mode": "view", "view_url": "<ссылка>", "page_size": 1}}`
   должен ответить без ошибки. У пустой базы ответ без строк — это нормально.

## Подключение существующей базы

1. Сделайте `notion-fetch` по ссылке на базу и сверьте свойства с таблицей выше.
2. Недостающие свойства можно добавить через `notion-update-data-source`, `ADD COLUMN …`.
   Свойства с другими именами можно переименовать через `RENAME COLUMN "Старое" TO "Новое"`.
   Оба шага — только с согласия пользователя.
3. Варианты select меняются через `ALTER COLUMN "Где" SET SELECT(...)`. Перечислите **все** существующие
   варианты и добавьте новые. Вариант, которого нет в списке, удалится.

## Чтение и запись

- **Последние записи (SQL).** Имена таблиц и колонок берите из `<sqlite-table>` в ответе `notion-fetch`,
  не угадывайте их:

  ```sql
  SELECT "Товар", "date:Дата:start", "Сумма", "Количество", "Единица", "Цена за ед.", "Категория", "Тип",
         "Необходимость", "Где", "Источник", "Счёт", "Детали"
  FROM [collection://…] ORDER BY "date:Дата:start" DESC LIMIT 50
  ```
- **Запись.** `notion-create-pages` с `parent: {"type": "data_source_id", "data_source_id": "<uuid без collection://>"}`.
  В одном вызове можно передать до 100 страниц. Передавайте `allow_async: false`, чтобы сверка после записи
  видела новые строки. Свойства страницы:
  - `"Товар"`;
  - `"date:Дата:start": "2026-10-14"` и `"date:Дата:is_datetime": 0`;
  - `"Сумма"`, `"Количество"`, `"Цена за ед."` — числами;
  - select — строкой с точным именем варианта;
  - `"Детали"` — строкой.

  Если нужного варианта select нет, сначала добавьте его в схему (см. выше). Только потом пишите строку.
