# Если что-то не работает

Команды ниже запускаются из каталога `scripts/` скилла `expense-tracker` (или попросите Claude выполнить их):

- ручная установка: `~/claude-expense-tracker/plugins/expense-tracker/skills/expense-tracker/scripts/`;
- маркетплейс: `~/.claude/plugins/cache/claude-expense-tracker/expense-tracker/<версия>/skills/expense-tracker/scripts/`. Точный путь: `dirname "$(find ~/.claude/plugins -name ypay.py -path '*expense-tracker*' | head -1)"`.

Коды выхода:

| Код | Значение |
|---|---|
| `0` | Всё хорошо |
| `1` | Ошибка: сообщение в stderr |
| `2` | Неверные аргументы. У `config.py check` это значит, что `config.json` не найден или невалиден |
| `3` | Нужен вход: сессия банка истекла или вы не вошли в Ленту либо Еду |

## Код 3 от `ypay.py`: банк просит PIN

Сессия банка живёт поверх Яндекс ID около 15 минут без активности, потом банк просит PIN или код.

1. Claude должен спросить вас, прежде чем открывать окно. Ответьте «да, открой».
2. Он запустит `uv run ypay.py login`, и окно Chrome развернётся на странице истории операций.
3. Введите PIN или код. Окно можно свернуть, оно свернётся и само при следующем запуске.
4. Повторите запрос: «ещё раз».

Из терминала `ypay.py` сам разворачивает окно и ждёт входа до 5 минут.

Если код 3 повторяется сразу после входа, проверьте, что страница истории операций открывается в этом окне без запроса кода. Если окно открылось на странице входа Яндекс ID, войдите заново.

## Код 3 от `lenta.py` или `eda.py`

- **Лента.** `uv run lenta.py login` открывает личный кабинет lenta.com. Войдите по телефону. Чеки из магазинов видны, если к аккаунту привязана «Карта №1».
- **Яндекс Еда.** Используется тот же Яндекс ID, что у банка: если `ypay.py` работает, вход уже есть. Иначе запустите `uv run eda.py login` и войдите в Яндекс ID.
- Код 3 в Еде бывает и тогда, когда заказов нет совсем: эти два случая сайт не различает. Если банк работает, а Еда отвечает 3, скорее всего, заказов просто нет.

## Chrome не найден

- **macOS.** Нужен Google Chrome (в `/Applications` или `~/Applications`). Проверка: `mdfind "kMDItemCFBundleIdentifier == 'com.google.Chrome'"` печатает путь к приложению. Если пусто (например, Spotlight выключен): `ls -d "/Applications/Google Chrome.app" ~/Applications/"Google Chrome.app"`. Скрипт запускает Chrome через `open -na "Google Chrome"`, поэтому место установки не важно.
- **Linux.** Проверка: `command -v google-chrome || command -v google-chrome-stable || command -v chromium || command -v chromium-browser`. Подойдёт любой из этих бинарей. Snap- и Flatpak-сборки Chromium (на Ubuntu `chromium` и `chromium-browser` — это snap) не пускают к профилю в скрытом каталоге `~/.expense-tracker`: скрипт сразу скажет об этом. Поставьте Chrome из .deb или .rpm либо перенесите данные в нескрытый каталог: `export EXPENSE_TRACKER_HOME=~/expense-tracker`.
- **Chrome стоит в нестандартном месте.** Укажите путь явно: `export EXPENSE_TRACKER_CHROME=/path/to/chrome`. На macOS можно указать имя или путь `.app`.
- Браузеры Playwright (`playwright install`) не нужны и не используются.

## Chrome не открыл CDP-порт / порт занят

Скрипт ждёт порт отладки (по умолчанию 9223) до 20 секунд.

- Проверьте, кто держит порт: `lsof -nP -iTCP:9223 -sTCP:LISTEN`.
- Если это чужой процесс, выберите другой порт: `python3 config.py set cdp_port 9333` или `export EXPENSE_TRACKER_CDP_PORT=9333`. Допустимы порты 1024–65535.
- Если на порту уже висит Chrome с *другим* профилем, скрипт подключится к нему, и там не будет ваших сессий. Закройте его или смените порт.

## Профиль занят другим Chrome

Если Chrome с профилем `~/.expense-tracker/chrome-profile` уже запущен *без* порта отладки, новый экземпляр с этим профилем не стартует, и порт не поднимется. Так бывает, если вы открыли профиль вручную.

- Закройте все окна этого экземпляра и повторите запуск.
- Если Chrome упал и оставил блокировку, проверьте, что процесса нет (`pgrep -fl chrome-profile`), и удалите `~/.expense-tracker/chrome-profile/SingletonLock`.

## `PersistedQuery…` / «свежий operationId тоже не принят»

Банк выкатил новую версию сайта. Обычно `ypay.py` сам открывает страницу истории, берёт новый `operationId` и сохраняет его в `~/.expense-tracker/ypay-feed-hash`.

- Если не вышло, удалите кэш (`rm ~/.expense-tracker/ypay-feed-hash`) и повторите. Возможно, сначала понадобится войти: код 3.
- Ошибки «запрос ленты на странице истории не найден» или «свежий operationId тоже не принят» означают, что банк поменял сам запрос, а не только его hash. Нужна правка `ypay.py`. Откройте issue и приложите текст ошибки *без* заголовков и cookies.

## Notion: квота SQL, не та база, нет доступа

- **Квота.** У SQL-запросов коннектора есть почасовая квота. Когда она кончается, скилл читает базу через сохранённое представление (`notion.default_view`, mode view). Если представление не задано: `python3 config.py set notion.default_view "https://www.notion.so/…?v=…"`.
- **`config.py check` возвращает 2.** Конфиг не найден или в нём нет `notion.data_source`. Скажите Claude «настрой учёт трат» или задайте значение вручную через `config.py set`.
- **Коннектор не видит базу.** Проверьте `/mcp` в Claude Code: должен быть Notion от claude.ai. В Notion у коннектора должен быть доступ к странице с базой.
- **Пропали варианты select.** При изменении свойства через `notion-update-data-source` нужно перечислить *все* существующие варианты. Если варианты пропали, их можно вернуть из истории версий страницы в Notion.

## Лента: пустой список или «нет блока Товары»

- `shop` по умолчанию показывает последний месяц. Для более старых чеков задайте период: `--since 2026-09-01 --until 2026-09-30`.
- `orders` и `order` читают текст страницы. Если Лента поменяла вёрстку или подписи, разбор сломается, и скрипт выйдет с кодом 1. В этом случае нужна правка `lenta.py`.

## Linux

- **Графический сеанс обязателен.** Без `DISPLAY` или `WAYLAND_DISPLAY` скрипт сразу выходит с ошибкой: headless не используется. На сервере без дисплея запускайте через `xvfb-run`, но для входа с PIN всё равно понадобится видеть окно, например через VNC.
- **Wayland.** Окно может не сворачиваться из программы: это ограничение композитора. Помогает запуск Chrome под XWayland: `export EXPENSE_TRACKER_CHROME_ARGS="--ozone-platform=x11"`. Или просто сверните окно вручную.
- **Связка ключей.** При первом запуске GNOME Keyring или KWallet могут попросить разблокировку: Chrome шифрует ими cookies профиля. Лучше разблокировать связку при входе в систему. Есть и обходной путь: `EXPENSE_TRACKER_CHROME_ARGS="--password-store=basic"`. Но тогда cookies профиля, включая сессию банка, хранятся на диске почти без защиты, и их может прочитать любой процесс от вашего пользователя.
- **Часовой пояс.** Задаётся в `config.json` (`timezone`, формат IANA, например `Europe/Moscow`). От него зависят даты операций.

## Прочее

- **`uv: command not found`.** Поставьте uv: <https://docs.astral.sh/uv/getting-started/installation/>. Если только что поставили, а команда не находится — установщик положил uv в `~/.local/bin`, а сессия Claude Code этого ещё не видит: перезапустите Claude Code или вызывайте `~/.local/bin/uv`.
- **Суммы в отчёте не сходятся с банком.**
  - Проверьте холды: их сумма может измениться после проведения.
  - Проверьте возвраты: они приходят отдельной операцией.
  - Проверьте подписки с возмещением: они записываются нетто.
- **`build_report.py` выходит с кодом 2.** Сообщение начинается с `build_report:` и называет проблему. Обязательны колонки `date`, `item`, `amount`, по-английски или по-русски. Даты — `YYYY-MM-DD` или `DD.MM.YYYY`. Сверьтесь с [`examples/demo-month.csv`](../examples/demo-month.csv).
- **«прочитано 40 страниц, дальше не листаю».** `ypay.py` листает не больше 40 страниц ленты. Сузьте период через `--since`.
- **Скиллы не появились после установки.** Перезапустите Claude Code. При ручной установке проверьте, что в `~/.claude/skills/` лежат все три симлинка и они не битые: `ls -lL ~/.claude/skills/`.
