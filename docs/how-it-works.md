# Как это работает

Плагин состоит из трёх скиллов и набора небольших скриптов. Скиллы описывают, *что* делать и как разговаривать с пользователем. Скрипты достают данные из банка, Ленты и Еды и строят отчёт. В Notion Claude пишет сам, через Notion-коннектор.

```text
                       ┌────────────────────────── Claude Code ───────────────────────────┐
  «разберём траты» ──▶ │ скилл expense-tracker                                            │
                       │   ├─ читает ~/.expense-tracker/profile.md и config.json          │
                       │   ├─ uv run ypay.py / lenta.py / eda.py ──▶ свёрнутый Chrome     │
                       │   │                                         (свой профиль, CDP)  │
                       │   │                                           ├─ bank.yandex.ru  │
                       │   │                                           ├─ lenta.com       │
                       │   │                                           └─ eda.yandex.ru   │
                       │   ├─ python3 guess_combo.py (подбор состава по прошлым ценам)    │
                       │   └─ Notion-коннектор ──▶ база «Расходы по товарам»              │
                       └──────────────────────────────────────────────────────────────────┘
```

## Скиллы

| Скилл | Когда срабатывает | Что делает |
|---|---|---|
| `expense-tracker` | «разберём траты», «запиши трату», «сверь платежи», «сколько я потратил на …» | Сверяет платежи с базой, предлагает догадки, после ответа пользователя записывает строки и сверяет сумму |
| `expense-tracker-setup` | «настрой учёт трат», первый запуск, «перелогинь банк» | Проверяет зависимости, создаёт или подключает базу Notion, пишет `config.json`, помогает войти в сервисы, заводит `profile.md` |
| `expense-report` | «итоги месяца», «отчёт за октябрь» | Выгружает строки месяца из Notion в CSV, запускает `build_report.py`, пишет выводы |

Скрипты лежат в `skills/expense-tracker/scripts/`. Два других скилла вызывают их по относительному пути `<каталог скилла>/../expense-tracker/scripts/…`. Поэтому все три скилла должны лежать рядом: в плагине так и есть, а при ручной установке это три симлинка в `~/.claude/skills/`.

## Браузер: свёрнутый Chrome по CDP

У банка, Ленты и Еды нет публичного API. Зато их сайты сами ходят в свои JSON-API из браузера, где вы вошли. Скрипты повторяют эти запросы.

- **Отдельный профиль.** `browser.py` запускает установленный Google Chrome (на Linux можно Chromium) с `--user-data-dir=~/.expense-tracker/chrome-profile` и `--remote-debugging-port=9223`. Ваш основной профиль Chrome не используется. Каталог создаётся с правами `0700`.
- **Запуск.** На macOS: `open -g -j -na "Google Chrome" --args …`, окно не выходит на передний план. На Linux берётся первый найденный в `PATH` из `google-chrome`, `google-chrome-stable`, `chromium`, `chromium-browser` и запускается отдельным процессом в новой сессии, так что Chrome переживает завершение скрипта. Нужна графическая сессия (`DISPLAY` или `WAYLAND_DISPLAY`). Свой бинарь задаётся через `EXPENSE_TRACKER_CHROME`, дополнительные флаги — через `EXPENSE_TRACKER_CHROME_ARGS`.
- **Подключение.** Playwright подключается через `connect_over_cdp`. Браузеры Playwright не скачиваются, используется ваш Chrome.
- **Окно свёрнуто.** Через CDP `Browser.setWindowBounds{windowState: "minimized"}`. Если окружение этого не позволяет (некоторые композиторы Wayland), шаг молча пропускается. Новые вкладки не создаются: на macOS новая вкладка разворачивает окно. Работа идёт в первой вкладке.
- **Окно показывается только для входа** (команда `login`) и только после согласия пользователя.
- **Chrome остаётся жить** между вызовами: Playwright только отключается. Повторный вызов работает быстро, сессии сохраняются.
- **Без headless и подмены User-Agent.** Сайты считают такое ботом, и это был бы обход их защиты.

Чтобы повторить запрос SPA, `browser.py` открывает страницу и перехватывает заголовки первого запроса страницы к её API (`capture_headers`). Потом выполняет `fetch` изнутри страницы с `credentials: "include"` (`fetch_json`). Значения заголовков нигде не печатаются: в них сессионные токены.

## Яндекс Пэй: GraphQL кабинета банка

`ypay.py` читает ленту операций веб-кабинета `bank.yandex.ru`.

- **Запрос.** POST на `/transactions/api/graphql?operationId=<hash>`, операция `TransactionsFeedPfm`. Это *persisted query*: вместо текста запроса отправляется его sha256. Листание идёт по `cursor`: сначала `pendingItems` (холды), потом `items`. Чтение останавливается на первой операции старше `--since` или по лимиту `-n`.
- **Часовой пояс** передаётся в заголовке `x-yabank-time-zone` из `config.json` (`timezone`). По умолчанию берётся системный пояс.
- **Автообновление operationId.** Когда банк выкатывает новый фронт, старый hash перестаёт приниматься (ошибка `PersistedQuery…`). Тогда скрипт открывает страницу истории операций, ловит `operationId` из запроса самой страницы и сохраняет его в `~/.expense-tracker/ypay-feed-hash`.
- **Сессия банка.** Это отдельная сессия поверх Яндекс ID (cookie `yabank-sessionuuid`). Без активности она живёт около 15 минут, потом банк просит PIN или код. Признаки истёкшей сессии: нет этой cookie, ответ 401/403, ошибка GraphQL про пользователя. В этом случае:
  - из агента (stderr не терминал) скрипт выходит с **кодом 3**. Claude спрашивает вас и только потом запускает `ypay.py login`, которая разворачивает окно;
  - из терминала скрипт сам разворачивает окно и ждёт входа до 5 минут.

## Лента и Яндекс Еда: API из страницы

- **Лента** (`lenta.py`).
  - `shop` и `shop-detail` — покупки в магазинах по «Карте №1». Это JSON `api-gateway/v1/purchases` и `…/purchases/details`: позиции, количество, весовые, цена за кг. Заголовки берутся со страницы истории заказов.
  - `orders` и `order` — онлайн-заказы. Их скрипт читает из текста страницы, потому что JSON для них не найден. Это хрупкое место: оно завязано на русские подписи интерфейса.
  - Если вход не выполнен, страница не делает запросов к API, и скрипт выходит с кодом 3.
- **Яндекс Еда** (`eda.py`).
  - `orders` — список заказов, включая магазины внутри Еды. `order` — позиции и итоги заказа. Источник — `eats/v1/orders-info/…`.
  - Вход тот же Яндекс ID, что у банка: после `ypay.py login` отдельный вход обычно не нужен. Если всё же нужен, есть `eda.py login`. Без входа скрипт выходит с кодом 3.
  - Возврат за непривезённое приходит в банке отдельной операцией. Его учитывают как поправку к заказу.

## Notion: через коннектор

Скрипты в Notion не ходят. Читает и пишет сам Claude через Notion-коннектор claude.ai: `notion-fetch`, `notion-query-data-sources`, `notion-create-pages`, `notion-update-data-source`. Адрес базы берётся из `config.json`:

- `notion.data_source` — `collection://…`. Сюда пишутся строки, отсюда читаются SQL-запросом.
- `notion.default_view` — ссылка на представление `…?v=…`. Через него идёт запасное чтение (mode view), когда кончилась почасовая квота SQL.

Схема базы описана в [`references/notion-schema.md`](../plugins/expense-tracker/skills/expense-tracker/references/notion-schema.md). Её можно расширять: добавлять категории, магазины в «Где», поля. При изменении select-свойства перечисляются все старые варианты, иначе они пропадут.

## Поток: платёж → догадка → ответ → запись → сверка

1. **Контекст.** Скилл читает `profile.md` (ваши магазины, переводы, привычки) и последние записи в базе. Новые строки оформляются так же, как прошлые записи этого магазина.
2. **Платежи.** `uv run ypay.py --since <дата последней записи> --json`. Отказы (FAIL) пропускаются: это повторные попытки. Поступления — не траты. Холды помечаются: сумма может измениться.
3. **Сверка.** Платежи сопоставляются со строками базы по дате и сумме. Остаётся список незаписанного.
4. **Состав.**
   - Платёж в Ленте или Еде: чек или заказ подтягивается скриптом. Весовые товары берутся по фактическому весу, сбор за сборку или доставку идёт отдельной строкой.
   - Мелкий платёж без чека: `guess_combo.py` подбирает комбинацию позиций по прошлым ценам магазина. Строка помечается в «Детали»: «состав подобран по прошлым ценам».
   - Перевод человеку: смысл берётся из `profile.md`, если он там есть. Иначе Claude спрашивает.
5. **Вопрос.** Незаписанное показывается по дням, от свежих к старым, коротким пронумерованным списком с догадками.
6. **Ответ.** Вы отвечаете номерами: «2 — такси», «5 не записывай», «да». «Доверяю» или «просто добавь» означает записать всю показанную пачку.
7. **Запись.** Только после ответа. Одна строка — одна позиция чека. Подарки пишутся отдельно, как «<Товар> (в подарок)». Общие покупки делятся.
8. **Сверка суммы.** Сумма записанных строк сравнивается с банком, результат сообщается одной строкой.
9. **Память.** Если выяснилось устойчивое правило (как магазин называется в банке, что значит перевод), оно дописывается в `profile.md`, и об этом сообщается одной строкой.

## Форматы данных

### `~/.expense-tracker/config.json`

```json
{
  "notion": {
    "data_source": "collection://00000000-0000-0000-0000-000000000000",
    "default_view": "https://www.notion.so/00000000000000000000000000000000?v=00000000000000000000000000000000"
  },
  "timezone": "Europe/Moscow",
  "cdp_port": 9223
}
```

Значения выше — заглушки. Управление настройками:

```bash
python3 config.py show                                          # текущие настройки
python3 config.py check                                         # 0 — config.json валиден, 2 — нет
python3 config.py set notion.data_source "collection://…"       # ключ в точечной нотации
python3 config.py path [home|config|profile|chrome-profile|ypay-feed-hash]   # путь к данным
```

Переменные окружения:

- `EXPENSE_TRACKER_HOME` — каталог данных (по умолчанию `~/.expense-tracker`);
- `EXPENSE_TRACKER_CDP_PORT` — порт отладки Chrome (имеет приоритет над `cdp_port`);
- `EXPENSE_TRACKER_CHROME` — путь к бинарю Chrome или Chromium (на macOS можно имя или путь `.app`);
- `EXPENSE_TRACKER_CHROME_ARGS` — дополнительные флаги Chrome, например `--ozone-platform=x11` или `--password-store=basic`.

### Вывод `ypay.py --json` (JSON Lines, одна операция на строку)

```json
{"id": "…", "date": "2026-10-31T19:42:10+03:00", "amount": -412.0, "currency": "RUB",
 "status": "CLEAR", "title": "Пятёрочка", "description": "Супермаркеты",
 "cashback": 4.0, "cashback_currency": "PLUS"}
```

- `amount` < 0 — списание, > 0 — поступление.
- `status`: `CLEAR` (проведена), `HOLD` (холд), `FAIL` (отказ).
- `--csv` выдаёт те же поля в CSV, без флагов печатается таблица.

### Лента и Еда

- `lenta.py shop` (JSON Lines): `{id, datetime, sum, store, address}`.
- `lenta.py shop-detail ID`: `{datetime, pay_sum, items: [{name, qty, weighted, price, price_per_kg, sum}]}`.
- `lenta.py orders` (JSON Lines): `{order, status, when, address, sum}`. `order NUM` печатает текст состава заказа.
- `eda.py orders` (JSON Lines): `{order, info: [...]}`.
- `eda.py order NR`: `{order, created_at, items: [{name, sum, sum_before, unit_price}], totals: [{label, sum, sum_before}]}`. У весовых `sum` — по факту, `sum_before` — по заказанному весу.

### Подбор состава

```bash
python3 guess_combo.py 412 "Хлеб=59" "Сыр=254" "Молоко=99" "Кефир=89" --max-items 4 --tolerance 0 --top 12
python3 guess_combo.py 412 --prices prices.json     # [{"name": "Хлеб", "price": 59}, ...]
```

Комбинации сортируются по отклонению от суммы, затем по числу позиций, так что короткие идут первыми.

### CSV для отчёта

`expense-report` выгружает строки месяца из Notion в `~/.expense-tracker/reports/YYYY-MM.csv`: UTF-8, разделитель `;`, первая строка — заголовок. Перед построением отчёта число строк и сумма в CSV сверяются с контрольным `COUNT`/`SUM` по базе.

```text
date;item;category;necessity;where;amount;details
2026-10-03;Молоко 2,5%;Молочное и яйца;Базовое;Пятёрочка;99;
2026-10-03;Шоколад (в подарок);Снеки и сладкое;Необязательное;Пятёрочка;149;
2026-10-05;Хлеб;Хлеб;Базовое;Пятёрочка;59;состав подобран по прошлым ценам
```

- Колонки соответствуют свойствам Notion: Дата (`YYYY-MM-DD`), Товар, Категория, Необходимость, Где, Сумма, Детали.
- Дополнительно можно передать `qty` (Количество) и `type` (Тип).
- Признаки «подарок» и «состав подобран» вычисляются из названия и деталей.
- Полный пример: [`examples/demo-month.csv`](../examples/demo-month.csv).

Сборка отчёта:

```bash
python3 report/build_report.py --csv month.csv --title "Октябрь 2026" \
    [--findings findings.html] [--out report.html] [--config report-config.json]
```

`build_report.py` понимает и разделители `,` и TAB, даты `DD.MM.YYYY` и суммы вида `1 234,50`. Вместо английских имён колонок можно использовать русские названия свойств (Дата, Товар, Категория, …).

Необязательный `--config` задаёт правила отчёта. Скилл хранит их в `~/.expense-tracker/report-config.json` и создаёт этот файл только с вашего согласия. Образец — [`scripts/report/config.example.json`](../plugins/expense-tracker/skills/expense-tracker/scripts/report/config.example.json):

```json
{
  "big_amount": 2000,
  "big_categories": ["Электроника"],
  "group_by": "category",
  "groups": {"Подписки": "Подписки и цифровое", "VPN / хостинг": "Подписки и цифровое"},
  "habits": [
    {"label": "Фастфуд", "match": ["Шаурма", "Бургер"], "unit": "раз"},
    {"label": "Кофе с собой", "match": ["Капучино", "Латте"], "unit": "шт"}
  ]
}
```

- `big_amount` и `big_categories` — порог и категории крупных разовых покупок. Они входят в итог, но не искажают графики по дням, «Необязательное» и «Где».
- `group_by` — группировать по «Категории» (`category`) или по «Типу» (`type`). `groups` переименовывает или сливает группы.
- `habits` — необязательные «привычки», которые считаются отдельно. `match` — подстроки названия, `categories` и `where` — фильтры. `unit: "раз"` считает визиты, остальные единицы — штуки. Вместо объекта можно передать просто список `habits`. Выводы (`--findings`) пишутся под конкретный месяц по образцу [`references/findings-template.html`](../plugins/expense-tracker/skills/expense-tracker/references/findings-template.html).
